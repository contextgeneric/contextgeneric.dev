# CGP v0.7.1 - Grouping components with namespaces and paths

**CGP v0.7.1** has been released, and it comes with major ergonomic improvements to manage CGP components at scale. In this blog post, we will explore the problems with managing CGP components, and how the new namespace feature in CGP v0.7.1 helps solve the problem.

## The challenges of scaling CGP

Up until now, one of main challenges of using CGP is on the boilerplate of using `delegate_components!` to wire CGP providers, especially as the number of CGP components grow within an application. When there are too many entries inside `delegate_components!`, developers quickly get lost on what they should pay attention to, and it gives the impression that the application becomes too complex.

To demonstrate the challenge, we will make use of a simple web application as an example. Suppose that we want to build a simple social media web app, we could use CGP to define modular traits to expose simple CRUD capabilities for managing users and posts. A simplified version of the traits would look something like follows:

```rust
#[cgp_component(UserManager)]
pub trait CanManageUser {
    fn create_user(&self, username: &str, email: &Email) -> Result<User, Error>;

    fn get_user(&self, user_id: &UserId) -> Result<User, Error>;

    fn update_user_data(&self, user_id: &UserId, user_data: &UserData) -> Result<(), Error>;
}

#[cgp_component(PostManager)]
pub trait CanManagePost {
    fn create_post(&self, title: &str, content: &str) -> Result<Post, Error>;

    fn get_post(&self, post_id: &PostId) -> Result<Post, Error>;

    fn update_post(&self, post_id: &PostId, content: &str) -> Result<(), Error>;

    fn delete_post(&self, post_id: &PostId) -> Result<(), Error>;
}
```

Our trait definitions are as straightforward as vanilla trait definitions, aside from the use of `#[cgp_component]` to turn them into CGP traits. The main advantage is that we can now define context-generic implementations for the traits. For example, we can implement production-ready providers as follows:

```rust
#[cgp_impl(new ProductionUserManager)]
impl UserManager {
    fn create_user(
        &self,
        #[implicit] database: &Database,
        username: &str,
        email: &Email,
    ) -> Result<User, Error> {
        // ...
    }

    fn get_user(&self, #[implicit] database: &Database, user_id: &UserId) -> Result<User, Error> {
        // ...
    }

    fn update_user_data(
        &self,
        #[implicit] database: &Database,
        user_id: &UserId,
        user_data: &UserData,
    ) -> Result<(), Error> {
        // ...
    }
}

#[cgp_impl(new ProductionPostManager)]
impl PostManager {
    fn create_post(
        &self,
        #[implicit] database: &Database,
        title: &str,
        content: &str,
    ) -> Result<Post, Error> {
        // ...
    }

    fn get_post(&self, #[implicit] database: &Database, post_id: &PostId) -> Result<Post, Error> {
        // ...
    }

    fn update_post(
        &self,
        #[implicit] database: &Database,
        post_id: &PostId,
        content: &str,
    ) -> Result<(), Error> {
        // ...
    }

    fn delete_post(&self, #[implicit] database: &Database, post_id: &PostId) -> Result<(), Error> {
        // ...
    }
}
```
