# `MatchWithValueHandlers`

Match an enum by building the per-variant handler list automatically, passing each payload as a bare
value.

## Overview

`MatchWithValueHandlers<Provider>` is the convenience matcher for the common case. Rather than spelling
out one adapter per variant, it synthesizes the handler list from the input type's own field list, so
adding a variant needs no change to the wiring. Each matched payload reaches `Provider` as a bare value,
which is the form to use when the per-variant handler is an ordinary computer over the payload type,
such as one generated by [`#[cgp_computer]`](../../macros/cgp_computer.md). It runs on a **context**,
the type a capability runs against. Like every CGP provider, it carries no runtime value.

It is the value-passing sibling of [`MatchWithFieldHandlers`](match_with_field_handlers.md): the two
differ by exactly one [`HandleFieldValue`](handle_field_value.md) wrapper, which
`MatchWithValueHandlers` adds so `Provider` receives the payload rather than a tagged field. `Provider`
defaults to [`UseContext`](../use_context.md), so each payload routes back through the context's own
handler wiring unless another provider is named.

The borrowed and multi-argument variants are `MatchWithValueHandlersRef` (over `&Input`),
`MatchWithValueHandlersMut` (over `&mut Input`), and the first-argument forms
`MatchFirstWithValueHandlers`, `MatchFirstWithValueHandlersRef`, and `MatchFirstWithValueHandlersMut`.

## Usage

It is in the prelude, so `use cgp::prelude::*;` is enough. It takes one optional type parameter, the
per-variant provider, and is most often wired through
[`UseInputDelegate`](../handler/use_input_delegate.md) so it is selected when the input is a given enum:

```rust
delegate_components! {
    App {
        ComputerComponent: UseInputDelegate<new AreaComputers {
            Circle: ComputeArea,
            Rectangle: ComputeArea,
            Shape: MatchWithValueHandlers,
        }>,
    }
}
```

A `Circle` input is handled directly by `ComputeArea`, while a `Shape` input is handled by
`MatchWithValueHandlers`, which synthesizes an adapter for each variant and routes each payload back
through the context's own `ComputerComponent`, so the `Circle` and `Rectangle` payloads reach
`ComputeArea` after all. `UseInputDelegate` is the correct wiring here because it keys on the input
type; it has no `open`-statement equivalent.

## When to reach for it, and when not

**Reach for `MatchWithValueHandlers` when every variant of an enum is handled the same way and each
handler wants the bare payload.** This is the usual case, and far shorter than spelling out the list
with [`MatchWithHandlers`](match_with_handlers.md). Reach for
[`MatchWithFieldHandlers`](match_with_field_handlers.md) when a handler needs the variant's tag attached
to its payload, and for [`MatchWithHandlers`](match_with_handlers.md) when the handlers cannot be
generated uniformly from the field list.

## Under the hood

`MatchWithValueHandlers<Provider>` is a type alias over
[`UseInputDelegate`](../handler/use_input_delegate.md) that dispatches on the input type and, for each
input, synthesizes the per-variant handler list from that input's [`HasFields`](../../traits/has_fields.md):

```rust
pub type MatchWithValueHandlers<Provider = UseContext> =
    UseInputDelegate<MatchWithFieldHandlersInputs<HandleFieldValue<Provider>>>;
```

Wrapping `Provider` in [`HandleFieldValue`](handle_field_value.md) is the one difference from
[`MatchWithFieldHandlers`](match_with_field_handlers.md), and it is what makes each payload arrive as a
bare value. The list itself is assembled by the `HasFieldHandlers` machinery described on
[`MatchWithFieldHandlers`](match_with_field_handlers.md#under-the-hood). The borrowed variants
additionally wire the `…RefComponent` handler traits through [`PromoteRef`](../handler/promote_ref.md),
so one struct serves both the by-value-of-reference and the by-reference interfaces.

## Related constructs

- [`MatchWithFieldHandlers`](match_with_field_handlers.md) — the sibling that keeps the variant tag on
  the payload; the two differ by one `HandleFieldValue` wrapper.
- [`MatchWithHandlers`](match_with_handlers.md) — the explicit form, when the list cannot be generated.
- [`UseInputDelegate`](../handler/use_input_delegate.md) — the input dispatcher this alias is built on.
- [`HandleFieldValue`](handle_field_value.md), [`UseContext`](../use_context.md) — the wrapper it adds
  and the default per-variant provider.
- [`HasFields`](../../traits/has_fields.md) — the field list the handler list is synthesized from.

The ideas behind it:

- [Dispatching](/docs/concepts/dispatching) — routing each variant of an enum to a handler.
- [Extensible variants](/docs/concepts/extensible-variants) — the enum pattern it serves.
