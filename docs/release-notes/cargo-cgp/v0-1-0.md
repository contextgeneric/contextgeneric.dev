# cargo-cgp v0.1.0

This page lists what the first release of `cargo-cgp` provides. The tool is the error toolchain of
[Context-Generic Programming (CGP)](/docs/), a Rust library whose macros generate traits and their
wiring: it rewrites CGP's compile errors to name their cause and prints the code the macros
generate.

Released on YYYY-MM-DD.

- **Release post:** [CGP v0.8.0 - cargo-cgp, new documentation, and namespaces](/blog/v0.8.0-release#diagnosing-wiring-with-cargo-cgp)
- **Crate:** [`cargo-cgp` 0.1.0 on crates.io](https://crates.io/crates/cargo-cgp/0.1.0)
- **Tag:** [v0.1.0](https://github.com/contextgeneric/cargo-cgp/tree/v0.1.0)

## Summary

`cargo cgp check` runs `cargo check` and rewrites the CGP errors it recognizes, tagging each with a
`[CGP-Exxx]` code for its class. `cargo cgp check` leads with the root cause for the classes it recognizes, and the tool does not yet reshape every class. `cargo cgp expand` prints a target's
macro expansion with CGP's type-level constructs written as macros again. `cargo cgp setup` and
`cargo cgp update` install and refresh the pinned nightly and the driver built against it.

## Compatibility

- **Minimum Rust version:** 1.96, for the front end that `cargo install` builds. The driver
  builds on the pinned nightly, `nightly-2026-11-16`, which `cargo cgp setup` installs, and a
  project's own builds keep its toolchain.
- **CGP version:** the tool recognizes the errors of [`cgp` v0.8.0](/docs/release-notes/cgp/v0.8.0),
  released beside it. Older CGP code compiles as it would under `cargo check`, but rewriting its
  errors is untested.
- **Platforms:** tested on Linux; macOS and Windows are untested.
- **Crates:** `cargo-cgp`, `cargo-cgp-driver`, `cargo-cgp-error-processing`, and
  `cargo-cgp-expand`, all at 0.1.0.

## Upgrading

This is the tool's first release, so there is nothing to upgrade from. Install it with
`cargo install --locked cargo-cgp` followed by `cargo cgp setup`, or through the Nix flake at
`github:contextgeneric/cargo-cgp/v0.1.0`, as [Installation](/docs/tooling/cargo-cgp/installation)
describes.

## New features

### Commands

- **`cargo cgp check`** forwards its arguments to `cargo check` and rewrites each CGP error it
  recognizes: it checks the program with Rust's next-generation trait solver to find the cause,
  names it in the headline, draws the dependency chain, and keeps rustc's own code beside the CGP
  code. Errors it does not recognize pass through unchanged, and rewriting applies to the crates of
  the workspace. The errors come in the order of the code they point at, so the output is the same
  on every run, however many threads the compiler checks on. See
  [Check](/docs/tooling/cargo-cgp/check).
- **`cargo cgp check --message-format=json`** prints the rewritten errors as JSON, the form an
  editor reads.
- **`cargo cgp expand`** prints the Rust one target's macros generate, writing a field tag as
  `Symbol!("width")`, a list as `Product![A, B]`, a field list as `Struct! { width: f64 }`, and a
  path as `Path!(@app.Component)`. `--item <PATH>` narrows the output to one module, type, or
  trait, and the other arguments go to `cargo rustc`. See [Expand](/docs/tooling/cargo-cgp/expand).
- **`cargo cgp setup`** installs the pinned nightly with `rustc-dev` and `llvm-tools` through
  rustup and builds the matching `cargo-cgp-driver` beside the front end.
- **`cargo cgp update`** reinstalls the tool when crates.io has a newer version in its release
  channel, then runs that version's `setup`.
- **`--version` and `--help`** print the version and the list of commands. See
  [Command reference](/docs/tooling/cargo-cgp/command-reference).

### Error codes

- **Whole-error codes:** 37 `CGP-E0xx` codes head a rewritten error, one per class of mistake,
  grouped by kind: a trait a context cannot use, conflicting wiring, structural mistakes, wiring
  that does not resolve, mistakes in a macro's input, and extensible data.
- **Dependency-step codes:** 24 `CGP-E1xx` codes label the lines of the dependency tree, for the
  path through the requirements and the cause at its end.
- **A provider's missing component key:** `CGP-E041` reports a provider header whose component key
  is not in scope, with the key's public import path, and a header that names its trait through a
  module that re-exports the trait without its key; `CGP-E070` reports a header whose derived key is
  not the component's, with a fix that names the key in the attribute.
- **Rewrites without a code:** an error the tool leaves unclassified still has its type-level
  names written as macros, shorter type names, and the generated traits' notes renamed to the
  consumer and provider traits.

See [Error codes](/docs/tooling/cargo-cgp/error-codes) for each code.

### Editor integration

rust-analyzer can run `cargo cgp check` on save through `rust-analyzer.check.overrideCommand`, so
the editor shows the rewritten errors. `CGP-E041`'s import is a fix the editor applies on the
provider trait's name and on a wiring key, marked preferred when one path imports the key, and
`CGP-E070`'s fix appears on the trait's name the same way. See
[Editor integration](/docs/tooling/cargo-cgp/editor-integration).

### Nix

The repository's flake builds both binaries against the pinned nightly without rustup, and
`nix run github:contextgeneric/cargo-cgp/v0.1.0 -- check` runs the tool without installing it.
